# Задание 1. Разбор tsconfig.json

Откройте `tsconfig.json` в корне проекта и для каждой строки напишите
**своими словами**, что она делает. Не копируйте документацию —
объясните так, как будто рассказываете одногруппнику.

## compilerOptions

### target
> отвечает за версию JavaScript, которую TypeScript должен сгенерировать. При очень старом target TypeScript будет вынужден переписать синтаксис некоторых новых конструкций в более старые и совместимые

### module
> Определяет формат модулей, который будет использоваться в проекте

### moduleResolution
> Отвечате за то, как TypeScript должен понять, куда ведет import. Влияет на форму записи "рута" зависимости

### strict
> Переключатель строгой проверки типов. При значении true TypeScript включает сразу несколько дополнительных проверок, которые помогают находить потенциальные ошибки еще на этапе компиляции

### strictNullChecks
> Влияет на проверку пустых значений в коде. Компилятор более строго проверяет присваивание пустых значений для переменных. При значении true он отдельно учитывает null и undefined и без проверки не позволяет использовать значений, которое потенциально может быть пустым

### esModuleInterop
> Упрощает совместное использование ES Modules и CommonJS модулей. В основном позволяет удобнее импортировать CommonJS библиотеки через классический синтаксис import ... from ...

### skipLibCheck
> Отключает полную проверку файлов с описанием типов .d.ts, в том числе типов сторонних библиотек из node_modules.

### forceConsistentCasingInFileNames
> Проверяет регистр букв в именах файлов и путях импортов. Чтобы имена файлов не различались в формате написания

### outDir
> Определяет директорию, в которую TypeScript будет складывать результат компиляции.

### rootDir
> Определяет корневую директорию исходного кода относительно которой TypeScript будет сохранять структуру папок при компиляции.

## include
> Определяет какие файлы и директории должны входить в TypeScript проект

## exclude
> Определяет какие директории и файлы нужно исключить из файлов найденных через include

# Задание 1.2. Включение флагов

Для каждого пункта ниже:
1. Определите, какой флаг нужно поменять в `tsconfig.json`.
2. Внесите изменение.
3. Запустите `npm run check`.
4. Запишите результат в `task1.md`.

---

### 1. Строгие проверки типов
Включите опцию, которая делает `null` и `undefined` отдельными типами,
а не «совместимыми со всем». Без неё код с `null` компилируется, с ней — нет.

**Ваш ответ:** "strictNullChecks": true

---ммм

### 2. Проверка `this`
Включите опцию, которая ругается, если внутри функции используется `this`,
но функция не является методом класса (то есть `this` не определён).

**Ваш ответ:** "noImplicitThis": true

---

### 3. Неявный `any`
Включите опцию, которая ругается, если переменная получает тип `any`
автоматически (например, функция без аннотаций параметров).

**Ваш ответ:** "noImplicitAny": true

---

### 4. Возврат из функции
Включите опцию, которая требует, чтобы **все** ветки функции возвращали значение,
если функция объявлена как возвращающая не-`void`.

**Ваш ответ:** "noImplicitReturns": true
